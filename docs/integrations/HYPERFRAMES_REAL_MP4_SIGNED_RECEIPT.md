# HyperFrames — real synthetic MP4 receipt bound to the isolated staging lease

**Experimental CI-only** in PR #164 DRAFT; not a deployed service or a customer-content path.

The existing independent renderer previously deleted its real 150-frame MP4 before a trusted receiver could inspect it. The opt-in `MODO_HF_STATIC_EXPORT_MODE=synthetic-ci-artifact` now writes a validated bounded synthetic MP4 to a newly created `/output/synthetic.mp4` within the disposable CI mount. Default renderer behavior is unchanged. The rootless Chrome image never receives database access or a receipt-signing private key.

The workflow `hyperframes-real-mp4-lease-receipt-ci.yml` compiles the existing MODO static exporter, generates an ephemeral signed 3-scene order (31+64+55 frames), renders H.264 video in an internal-only Docker network, and independently verifies signed renderer order, original payload SHA-256, MP4 ftyp, file SHA-256 and FFprobe metadata on the trusted runner.

Then the trusted runner creates a separate staging queue UUID job with the request hash of the original signed renderer payload; claims a lease; signs an Ed25519 v2 lease dispatch; atomically consumes it through the existing PostgreSQL restricted function. A **different in-memory attestor key** signs a receipt binding organization, project, job, worker, current lease fence/version/attempt, source renderer order and job ID, dispatch order digest, true output hash and MP4 byte length, H.264, dimensions, frame rate and frame count. An independently fetched queue row and actual measured video are required to validate the receipt; wrong MP4 hash, tampering, revoked key, wrong fence and stale queue lease fail. The receipt plus public key are written and re-read from disposable runner files; the MP4 and receipt are erased on cleanup. No private signing key is written or mounted into Docker.

**Strict limitation:** the lease is claimed AFTER the independent synthetic MP4 render for this laboratory proof, so the receipt does **not** establish prior authorization of the browser. A fully authenticated scheduler-to-browser dispatch and atomic final artifact/receipt commit remain unimplemented. Also outstanding: service authentication, durable revocation/audit, retention, visual parity with Remotion, browser sandbox hardening, and the known HyperFrames CLI Docker regression. No merge/deploy or production activation.
